# 会邀、会议记录和文档增量

工作上下文同时包含正在讨论的事、计划沟通的事和已经沉淀的资料。每次更新分别报告 IM、会邀、会后记录、文档版本和图片的覆盖情况；一个阶段成功不能替代整轮完成。

## 产品目标

- 会邀作为工作安排参与理解。保留日历、实例、起止时间、参会人和回复状态；取消、拒绝和周期日程主记录不当作已开会。
- 参会人的私聊进入候选。优先用账号 ID 核对现有私聊，姓名匹配不足时保留待核对；不创建会话，不因会邀自动监听，不覆盖手动设置和禁止名单。
- 会议结束后搜索可访问的记录。同名文件只是候选；只有显式附件或已核对的关联才能说明它属于这次会议。会前显示尚未结束，搜索未命中保留后续检查。
- 已准入文档按源版本、修改时间和正文 SHA256 检查更新。没有版本提示时重新读取正文；保留旧快照和读取失败，不把修改时间当作业务统计日。
- 日报、周报和会议材料中的图片单独缓存。记录章节、原图哈希、识别回执和未读原因；签名下载地址变化不等于正文变化，图中文字提取不等于底表核验。
- 会邀、IM、文档和图片文字保留各自证据类型，供工作主线关联与问答检索；不自动把会邀或模型解释升级为正式 Memory 或已完成进展。

## 可运行组件

`scripts/refresh-context.py` 是独立、显式触发的资料刷新入口，依赖 Python 3.9+、已登录的 `kdocs-cli` 和可读取当前用户日历的 WPS V7 身份。它与网页 Alpha 的 OAuth 群聊导入是不同的连接方式；不会让网页索取浏览器 Cookie，也不自动安装或改写全局 Skill。

配置及结果须放在 checkout 外的私有目录。配置最小示意如下，ID 均需替换成用户明确授权的真实来源：

```json
{
  "calendarId": "example-calendar",
  "ownerId": "example-owner",
  "rollingWindow": true,
  "start": "2026-01-01T00:00:00+08:00",
  "end": "2026-01-16T00:00:00+08:00",
  "documents": [{"id": "example-report", "allowed": true, "kind": "report"}],
  "maxImages": 12,
  "maxImagesPerDocument": 4,
  "maxPeerResolutions": 8,
  "vision": {"enabled": false}
}
```

```sh
python3 scripts/refresh-context.py --config "$CONTEXT_CONFIG" --output "$CONTEXT_OUTPUT"
THIRD_BRAIN_CONTEXT_PATH="$CONTEXT_OUTPUT/context.json" npm start
```

WPS V7 身份只从进程环境读取。开启图片理解时，还需明确提供模型 endpoint、model、keyEnv、输入输出价格上界、maxCny 和 maxCalls。默认不请求付费图片模型。费用在发送前保守预留，同一输出目录按北京时间累计；这不是服务商账单，也不替代宿主项目的总预算。

网页“来源”可以显示这份回执、会邀、监控候选、文档版本和本地原图。独立刷新组件负责采集与可追溯回执；个人工作台另有累计证据入库适配器。网页 Alpha 的原有群聊分析不会因此自动变成全源主线重建或定时分析。

## 运行和验收边界

每轮图片数、联系人身份核对和分页都有上限，剩余项保留待处理。历史文档图片尚未审计时显示覆盖缺口，不声称全量已读。导出正文仍在生成时保存任务 ID，下一轮继续；遇权限或限流停止对应连接，不绕过来源门禁。只有拥有本轮锁的进程负责释放锁。

验收分别检查：会邀及取消状态、私聊 ID 对齐、禁止名单、会后记录关联、版本变化、正文及图片哈希、图片缓存可回读、问答来源，以及完整／部分／失败回执。公开代码和示意材料不包含真实人员、企业经营数据、内部文档链接或运行配置。
