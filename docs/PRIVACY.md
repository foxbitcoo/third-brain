# 隐私与隔离

## 公开仓库不包含

- 维护者或测试用户的真实消息、文档、会议、人员关系、项目、群名和裁决；
- App Key、Access Token、Refresh Token、OAuth code、Cookie、WPS_SID、模型 Key 和请求日志；
- 私人飞书/WPS 文档、截图、附件、本机绝对路径和数据导出；
- 围绕人物、项目或群聊组织的叙事型合成数据集。

个人版的私有仓库也不得依赖“private 权限”存档 API Key、OAuth 凭证、WPS SID、原始办公正文或运行时数据。私有仓库中只允许进入 Spec、代码、测试和待扫描的公开候选。

测试只使用无业务叙事的最小不透明值；静态 Demo 只说明页面结构。

## 每位安装者的本地边界

- `.env.local` 保存该安装者自己的 App Key 和模型 Key，并被 Git 忽略；
- `.runtime/` 保存随机本地加密密钥、WPS Token、导入消息和分析结果，并被 Git 忽略；
- 目录和文件权限限制为当前系统用户；
- 本地密钥和密文位于同一账户下，主要防止误上传与磁盘明文泄漏，不抵御已控制本机账户的攻击者；
- 卸载时删除 `.env.local` 和 `.runtime/` 即可删除本地配置与数据。

独立的会邀／文档刷新入口另存于安装者显式选择、位于 checkout 外的私有目录。正文、图片及回执采用当前用户可读写的文件权限保存，**这部分目前是明文文件，并不经过 Alpha 的加密存储**。它不进入公开仓库；卸载和清理时还需处理该外部目录。

## 外部数据流

- WPS OAuth 和消息读取只发往 WPS 官方域名；
- 模型分析只发往安装者明确配置的 HTTPS 模型 API（或本机 loopback 地址）；
- 没有维护者遥测、分析 SDK 或远程后端；
- Alpha 群聊导入需点击分析才发送给模型。独立资料刷新默认不调用模型；只有用户在其配置中显式启用图片理解，才会在预算范围内向指定模型发送文档原图和局部上下文。

## Report to Issue

公开 Alpha 暂未提供 Report to Issue，也不暴露本地草稿或 HTTP 写入口。后续独立 Ticket 必须重新完成隐私边界、数据流和验收设计；在此之前，安装者不应将办公内容、凭证或运行产物粘贴到任何公开反馈渠道。

## 发布门禁

新能力先在个人版验证，再进入基于公开仓库当前 HEAD 建立的候选分支。候选分支运行通用泄漏扫描；维护者再用只存于私人环境的 denylist 扫描；最后从干净目录安装和启动。自动检查全绿后仍需维护者人工复核和用户确认；任一门禁失败都不得发布。
