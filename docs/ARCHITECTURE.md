# 本地试用架构

本仓库是第三大脑的公开版，不是个人版数据的镜像。通用能力先在个人版验证，然后以明确变更清单进入公开候选分支；隐私扫描和用户确认是推送公开仓库前的硬门。

```text
浏览器（127.0.0.1）
  → 本地 Node.js 服务
    → WPS 用户 OAuth
    → WPS 用户消息 MCP（只读）
    → 当前电脑的加密文件
    → 用户显式点击分析
      → 安装者自己配置的 OpenAI-compatible 模型 API
```

## 数据边界

- 服务只监听 `127.0.0.1`，不提供公网入口；
- App Key 与模型 Key 只从 `.env.local` 读取；
- OAuth Token、导入消息和分析结果只以 AES-256-GCM 密文写入 `.runtime/user-data`；
- 聊天消息只在用户选择群聊并点击导入后读取；
- 消息只在用户点击分析后发送给其明确配置的模型 API；
- 维护者没有远程后端，也无法读取安装者本地数据。

## 当前产品切片

当前只走通“选择来源 → 导入少量消息 → 模型提出候选 → 用户判断”的需求验证链。它不是完整记忆系统：尚未包含持续调度、来源自动扩张、L0/L1/L2 持久记忆、机器人发送、工作台嵌入或多用户服务端。

另有可显式运行的 `refresh-context.py` 资料入口：WPS V7 会邀、候选联系人及会后记录检查，与 KDocs 文档版本检查并行汇入本地回执。OTL 图片按块查询得到真实资源 ID，逐张获取新下载链接并缓存，避免大周报导出耗时导致图片地址提前失效。可选的图片理解记录来源、模型回执和费用；默认关闭。网页“来源”通过 `THIRD_BRAIN_CONTEXT_PATH` 加载这份回执并展示原图。该组件的明文存储边界及接入方式见 [会邀与文档接入](product/calendar-document-context.md)，不代替原 Alpha 的加密群聊导入链，也不自动生成正式工作事实。

公开版还包含独立的合成工作台验收切片。它在本地固定生成 7 个中性候选，每个候选都要通过精确 7/7 合成谱系验证；缺失、重复、未知或歧义谱系一律拒绝继续。冲突确认需要安装者从空白字段明确填写事件类型、业务事实和 ISO UTC 发生时间，三项缺一不可。该切片只保存候选层状态，不会自动创建或修改工作事件、工作线程或当前状态，也不会读取 WPS 数据。

公开 Alpha 暂未提供 Report to Issue：没有草稿生命周期、相关 HTTP 路由或外部提交通道。后续独立 Ticket 才能重新引入并验收该能力。

每位同事单独在自己的电脑安装，天然形成独立的 WPS OAuth、模型 Key 和本地数据空间。后续如果改成集中式服务，仍必须重新完成租户、用户和凭证隔离验证，不能直接把本地 Alpha 当生产架构。
