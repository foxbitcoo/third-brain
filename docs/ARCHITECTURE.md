# 本地试用架构

项目的两条业务流及工单记忆闭环见[项目架构图](architecture/business-memory-flow.md)；本文说明本地运行方式与数据边界。

本仓库是第三大脑的公开版，不是个人版数据的镜像。通用能力先在个人版验证，然后以明确变更清单进入公开候选分支；隐私扫描和用户确认是推送公开仓库前的硬门。

```text
浏览器（127.0.0.1）
  → 本地 Node.js 服务
    → WPS 用户 OAuth
    → WPS 用户消息 MCP（只读）
    → 当前电脑的加密文件
    → 用户显式点击分析
      → 安装者自己配置的 OpenAI-compatible 模型 API
```

## 数据边界

- 服务只监听 `127.0.0.1`，不提供公网入口；
- App Key 与模型 Key 只从 `.env.local` 读取；
- OAuth Token、导入消息和分析结果只以 AES-256-GCM 密文写入 `.runtime/user-data`；
- 聊天消息只在用户选择群聊并点击导入后读取；
- 消息只在用户点击分析后发送给其明确配置的模型 API；
- 维护者没有远程后端，也无法读取安装者本地数据。

## 新版工作台

`npm start` 自动构建 `apps/business-workbench` 并启动统一服务。React/Semi UI 五个页面与个人版采用同源通用组件；公开安装不包含个人数据。安装适配层将本人 OAuth 导入后的加密工作区投影为 `business-qa-v1`，保留原始发送者、时间、来源和引用定位。

扩展能力包括来源关注、会邀/文档版本与图片、看板快照、历史工单与引用回复、标准 Query、模型分流、只读查数循环、待审报告和 Memory 审计。它们使用同一后端实现，由安装者提供自己的授权来源和模型。详细输入见 [工作台配置](WORKBENCH.md)。

- 每次请求重新读取有效来源策略；排除来源同时隐藏依赖它的派生结论与 Memory。
- 每次模型问答返回前再次核对来源权限。
- 浏览器不能指定本地文件、模型凭据或任意 SQL；扩展文件由服务端显式配置，查数限定于已授权只读方案。
- Query 规划、实际查数、结果复核与报告分别留存；查询成功不代表业务原因已证实。
- Loop 有轮次、调用、预算和人工补充边界；Memory 记录原始证据、版本、适用性和实际注入。
- 旧 Alpha 可通过显式兼容命令启动；它不再是默认入口。

每位安装者的 OAuth、模型、持久化及连接器独立配置。此版本不是集中式多租户生产服务，不自动安装维护者的私人定时任务或对外发送办公信息。Report to Issue 仍未启用。

公开 Alpha 暂未提供 Report to Issue；该能力保留给后续独立 Ticket 重新定义和验收。
